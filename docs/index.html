Find vulnerabilities by proof, not by guessing.

noctis is an open-source black-box scanner written in Rust. Every check is a readable YAML feed that has to observe the vulnerable behaviour before it reports — and every finding is graded by how strong the evidence is.

How it works

From a list of open ports to proven findings.

Feed noctis what you already know about a host — it decides which checks apply, runs them against the live service, and only reports what it could actually demonstrate.

Describe the target

POST a host and its discovered services — a port and a service name, straight from nmap or your inventory.

Match & probe

Every feed whose services: match is scheduled and its steps run against the live service — HTTP, raw TCP, UDP, TLS, SSH or SNMP.

Prove & grade

A finding is raised only when a step observes the bug, then graded with an OpenVAS-style Quality-of-Detection score.

Why noctis

Signal you can gate a pipeline on.

Banner-matching scanners drown you in "maybe". noctis is built around evidence, readable checks, and protocols beyond the web.

Evidence, not guesses

Each finding carries a QoD score — 50 for a banner, 75 for a functional proof, 97 for an out-of-band callback or confirmed RCE.

Detection as data

Checks are YAML feeds, not compiled plugins. Read them, review them in a pull request, write your own — no recompile.

Beyond HTTP

Line & binary TCP dialogues, UDP, TLS, SSH and SNMP — find the exposed Redis, MongoDB or SNMP community, not just the web bug.

Byte-exact payloads

tcp_connect sends requests verbatim, so encoded path-traversal payloads survive — no URL normalisation silently "fixing" your exploit.

Blind bugs, caught

A built-in out-of-band callback server confirms Log4Shell, SSRF and XXE that never echo back in the response.

Built for pipelines

A REST API with webhooks, a multi-arch static image a few MB in size, and findings you can fail a build on.

tests/vulnerabilities/apache-httpd/CVE-2021-41773.yaml
{% raw %}
name: "Apache httpd 2.4.49 path traversal"
cves: [CVE-2021-41773]
severity: critical
services: [http, https]
confidence_base: 0.30

steps:
  - id: probe
    action: tcp_connect      # bytes sent verbatim
    port: "{{port}}"
    send: "GET /icons/.%2e/.%2e/etc/passwd HTTP/1.0\r\n\r\n"
    store_as: resp

  - id: prove
    action: match
    source: resp.banner
    pattern: "root:[x*!]:0:0"
    on_match:
      finding:
        confidence_delta: 0.65
        qod: 75
        evidence: "LFI confirmed — /etc/passwd readable"
{% endraw %}
Feeds

A detection is a file you can read.

No DSL to learn, no plugin to compile. A feed declares which services it targets and the steps that prove the bug.

  • 0, 1 or many CVEs per feed — misconfiguration checks and multi-CVE chains are first-class.
  • Self-contained — no shared knowledge base between checks, so results are reproducible.
  • Scriptable when you need it — Rhai with regex, crypto and binary pack/unpack builtins.
  • Tested both ways — every feed ships a vulnerable and a patched mock, asserting a true positive and a true negative.

Quick start

Running in under a minute.

Pull the image or build from source, then submit your first scan over the REST API.

docker
$ docker run --rm -p 8080:8080 \
    ghcr.io/fdarkshadow/noctis:latest
# 310 feeds bundled at /feeds —
# mount -v ./my-feeds:/feeds to use your own
from source
$ git clone https://github.com/fDarkShadow/noctis
$ cd noctis && cargo build --release
$ ./target/release/noctis serve --port 8080
